## Plan change: two tracks

Split the repo in two. Learning concepts alongside the build would slow the build down. Building the full local stack first gives a bird's-eye view, so later study can ask questions that span the system instead of narrow ones.

- **This repo** is now the stack track: run models on the PGX (llama.cpp, vLLM), write a from-scratch inference engine, make it faster (quantization, batching), and serve it. See `PLAN.md`.
- **The concepts track** (curriculum, maths, papers, and the micrograd work started today) moved to a separate repo, `research-engineer-curriculum`, and starts once the stack is done. `questions.md` collects the "why?" questions that will seed it.
- Guard against "configured but not understood": the engine has to match HF `transformers` logits.
- Noted: work vLLM services already use most of the PGX memory (~44 GB free). The stack shares the box with them.

Measured which local inference engines people actually use: GitHub, PyPI, Docker Hub, Hacker News, Hugging Face format counts, and r/LocalLLaMA via Apify (935 posts, about $1). Tier 1 is llama.cpp, Ollama and vLLM; SGLang is a clear number 4. On DGX Spark/GB10 posts vLLM leads, ahead of llama.cpp. Wrote usage guides for llama.cpp, Ollama, LM Studio, vLLM, SGLang and TensorRT-LLM, checked against official docs and NVIDIA's Spark playbooks.

PGX gotchas found: driver 580 can't start NGC containers newer than 26.02; sm_121 is unusual and some kernels are missing; TensorRT-LLM's Spark playbook was withdrawn; llama.cpp needs `CMAKE_CUDA_ARCHITECTURES=121a-real`, and its default port is now 9931.
